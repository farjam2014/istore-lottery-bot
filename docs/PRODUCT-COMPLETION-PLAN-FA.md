# iStore Lottery — تکمیل محصول بر اساس نقشه ۳۶ قابلیت

مبنای کار: شاخه `fix/async-errors-migration-lock` در commit `16f8e0f3c0723fa99b4471e87c3b4434dd157948`.
این سند معیار پذیرش است؛ وجود جدول یا endpoint به‌تنهایی به معنی تکمیل قابلیت نیست.

## اصول محصول
- شرکت‌کننده باید ثبت‌نام را مانند یک فرم کوتاه و قابل‌فهم تجربه کند.
- مدیر باید عملیات روزمره را از داخل گفت‌وگوی خصوصی ربات و با دکمه‌های Inline انجام دهد؛ وب‌پنل در این پروژه ابزار اصلی مدیریت نخواهد بود.
- در تمام جریان‌ها «بازگشت»، «منوی اصلی» و «لغو» متناسب با مرحله وجود داشته باشد.
- هیچ قابلیت حساس بدون تأیید صریح اجرا نشود.
- ثبت‌نام تا پایان تست‌های پذیرش بسته می‌ماند.

## فاز ۱ — معماری مکالمه و پنل تلگرامی

- [ ] منوی مدیر: داشبورد، شرکت‌کنندگان، کدها، کمپین، قرعه‌کشی، گزارش‌ها، رخدادها، تنظیمات
- [ ] ناوبری استاندارد: بازگشت، خانه، لغو، صفحه‌بندی و تازه‌سازی
- [ ] عملیات مدیر فقط برای ADMIN_ID و در private chat
- [ ] مدیریت خطای callback و پاسخ به callback query در همه مسیرها
- [ ] جلوگیری از callback تکراری و اجرای دوباره عملیات

## فاز ۲ — تجربه شرکت‌کننده

- [ ] اعتبارسنجی و نرمال‌سازی شماره و Instagram با پیام خطای راهنما

## محدودیت‌ها و تصمیم‌های محصول
- Telegram Bot API امکان تشخیص اینکه کاربر صفحه اینستاگرام را follow کرده یا شماره فروشگاه را در مخاطبین ذخیره کرده باشد، نمی‌دهد.
- تطبیق JSON فالوور تنها وقتی قابل اتکا است که کاربر خروجی معتبر و قابل‌تفسیر ارائه کند؛ این روش تأیید زنده فالوور نیست.
- پرداخت واقعی خارج از دامنه این انتشار است؛ فقط طراحی ماژولار و مدل داده آینده انجام می‌شود.
- حذف شرکت‌کننده به‌صورت soft delete باقی می‌ماند. آزادسازی مجدد کد فقط با سیاست شفاف و کنترل‌شده کمپین ممکن است.

## معیار پایان انتشار
- همه مسیرهای مدیریتی اصلی از تلگرام قابل انجام باشند؛ وب‌پنل وابستگی عملیاتی نداشته باشد.
- تست واحد، integration و end-to-end برای مسیرهای حیاتی سبز باشند.
- تست عملی با حساب آزمایشی و staging انجام شود.
- ثبت‌نام عمومی فقط با تأیید نهایی مدیر باز شود.
- پس از موفقیت و تأیید نسخه جدید روی VPS، پوشه نسخه قدیمی جداگانه و با حفظ backup حذف شود.
