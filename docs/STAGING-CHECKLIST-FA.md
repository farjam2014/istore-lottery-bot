# چک‌لیست تست پیش از استقرار

## قبل از اجرا
- [ ] از دیتابیس و کل پوشه پروژه روی سرور backup گرفته شده باشد.
- [ ] فایل `.env` موجود سرور حفظ شده و در بسته انتشار وجود نداشته باشد.
- [ ] نسخه Node و MySQL ثبت شده باشد.
- [ ] migration روی یک کپی از دیتابیس اجرا شده باشد.

## تست ثبت‌نام
- [ ] کاربر جدید از Business پیام «لاتاری» می‌فرستد.
- [ ] نام فارسی و نام با فاصله‌های اضافی بررسی می‌شود.
- [ ] لینک اشتراک شماره فقط برای همان Telegram ID معتبر است.
- [ ] شماره با ارقام فارسی/عربی و لاتین اعتبارسنجی می‌شود.
- [ ] ارسال شماره متعلق به شخص دیگر رد می‌شود.
- [ ] آیدی اینستاگرام با/بدون @ نرمال می‌شود.
- [ ] ارسال کارت مخاطب ناموفق، پیام تأیید اشتباه تولید نمی‌کند.
- [ ] کلیک دوباره روی دکمه تأیید باعث کد دوم نمی‌شود.
- [ ] قطع تلگرام/DB در میانه پردازش بررسی می‌شود.
- [ ] لغو و شروع مجدد و ادامه ثبت‌نام نیمه‌کاره بررسی می‌شود.

## تست پنل
- [ ] ورود با رمز درست و غلط.
- [ ] محدودیت تلاش ورود.
- [ ] جستجو و صفحه‌بندی.
- [ ] ویرایش با داده معتبر و نامعتبر.
- [ ] جلوگیری از شماره/اینستاگرام تکراری.
- [ ] غیرفعال‌سازی و فعال‌سازی.
- [ ] حذف منطقی، ثبت audit و آزادسازی کد.
- [ ] خروجی CSV در Excel و محافظت در برابر فرمول CSV.
- [ ] بستن ثبت‌نام و اطمینان از رد درخواست جدید.
- [ ] جلوگیری از اجرای قرعه‌کشی هنگام باز بودن ثبت‌نام.
- [ ] اجرای قرعه‌کشی فقط یک بار و ذخیره snapshot واجدان شرایط.

## تست عملیاتی
- [ ] `/health` وضعیت دیتابیس را درست گزارش کند.
- [ ] پیام‌های webhook در inbox ذخیره و پردازش شوند.
- [ ] پیام ناموفق پس از retry در failed قابل مشاهده باشد.
- [ ] پس از restart، پیام‌های processing دوباره به صف برگردند.
- [ ] تست بار ۱۰۰، ۵۰۰ و ۱۰۰۰ کاربر در staging اجرا شود.
- [ ] بازیابی backup روی دیتابیس آزمایشی با موفقیت انجام شود.

تا زمانی که این چک‌لیست روی staging انجام نشده، نسخه را برای کمپین بزرگ production-ready تلقی نکنید.
