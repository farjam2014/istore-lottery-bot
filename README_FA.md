# iStore Lottery Bot — نسخه ارتقای حرفه‌ای و متعادل

این بسته شامل کد برنامه، پنل مدیریت، مهاجرت دیتابیس، تست‌های پایه و مستندات است. فایل‌های محرمانه عمداً داخل بسته قرار نگرفته‌اند.

## پیش‌نیازها
- Node.js نسخه 20 یا بالاتر (نسخه 22 پیشنهاد می‌شود)
- MySQL 8.0 یا نسخه سازگار با InnoDB و JSON
- HTTPS فعال برای وب‌هوک تلگرام و پنل مدیریت
- دسترسی ALTER/CREATE روی دیتابیس هنگام اجرای migration

## متغیرهای محیطی
فایل `.env.example` را به `.env` کپی کنید و مقادیر واقعی را فقط روی سرور وارد کنید:
`BOT_TOKEN`, `WEBHOOK_SECRET`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `ADMIN_ID`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `PORT`, `REGISTRATION_OPEN`, `CONTACT_PHONE`.
هرگز `.env` را در ZIP، Git یا چت ارسال نکنید.

## نصب یا ارتقای دیتابیس
1. قبل از هر تغییری از دیتابیس dump بگیرید.
2. برای نصب تازه، `schema.sql` را اجرا کنید.
3. برای دیتابیس موجود، پس از backup دستور `npm run migrate` را اجرا کنید. این migration ستون‌ها و جدول‌های افزوده را به‌صورت idempotent ایجاد می‌کند؛ با این حال قبل از اجرا روی نسخه کپی دیتابیس آزمایش کنید.
4. سپس `npm ci` و `npm run check` و `npm test` را اجرا کنید.

## اجرا
- `npm start`
- مسیر سلامت: `/health`
- پنل مدیریت: `/admin`
- webhook: `/telegram/<WEBHOOK_SECRET>`
- هدر Telegram webhook باید `secret_token` برابر `WEBHOOK_SECRET` داشته باشد.
- `allowed_updates` باید حداقل `message`, `callback_query`, `business_message` را شامل شود.

## نکات نسخه
- وب‌هوک ابتدا در `webhook_inbox` ذخیره می‌شود و سپس توسط worker پردازش می‌شود. خطاهای موقت تا ۵ بار retry می‌شوند؛ موارد شکست‌خورده در داشبورد شمارش می‌شوند.
- کدها با `crypto.randomBytes` و rejection sampling ساخته می‌شوند.
- نشست‌های ثبت‌نام پس از ۲۴ ساعت عدم فعالیت منقضی می‌شوند.
- حذف شرکت‌کننده soft-delete است؛ کد قبلی در `released_codes` نگهداری و برای تخصیص بعدی قابل استفاده می‌شود. `lottery_code_history` سابقه تخصیص/آزادسازی را نگه می‌دارد.
- انتخاب برنده فقط پس از بستن ثبت‌نام انجام می‌شود و اجرای مجدد برای همان دوره قفل است. فهرست واجدان شرایط در `lottery_draw_participants` snapshot می‌شود.
- کد نمی‌تواند واقعاً تشخیص دهد کاربر شماره فروشگاه را در مخاطبین ذخیره کرده است؛ دکمه صرفاً تأیید خوداظهاری کاربر است.
- بررسی فالوور اینستاگرام خودکار نیست. واردکردن JSON و تطبیق آن هنوز به‌عنوان قابلیت جداگانه پیاده‌سازی نشده است.
- پرداخت آنلاین، چند کمپین هم‌زمان و سیستم امتیازدهی در این نسخه وجود ندارد.
- برای چند پردازشگر/چند instance، worker فعلی تک‌پردازه است؛ پیش از scale-out باید صف به worker مستقل و claim اتمیک چند instance تبدیل شود.
- بررسی فالوور با فایل JSON اینستاگرام، جوین اجباری کانال، نمودارهای تحلیلی، بازیابی خودکار نشست کاربر پس از انقضای ۲۴ ساعته و سامانه چندکمپینی در این بسته تکمیل نشده‌اند.
- محدودیت تلاش ورود پنل در حافظه همین پردازش است؛ در چند instance باید به Redis/DB منتقل شود.
- برای قرعه‌کشی مستقل و قابل ممیزی، `draw_seed` فعلی به‌تنهایی سند اثبات‌پذیر انتخاب نیست؛ snapshot شرکت‌کنندگان و انتخاب با `crypto.randomInt` ثبت می‌شوند.

## تست
`npm run check` و `npm test`

تست بار و تست end-to-end با Telegram و MySQL واقعی هنوز باید در محیط staging اجرا شوند. اجرای این بسته روی سرور اصلی بدون backup، migration آزمایشی و smoke test توصیه نمی‌شود.
